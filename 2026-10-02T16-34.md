# Я пользуюсь ubuntu linux

Как я могу запаковать файл в многотомный архив, чтобы размер тома не превышал 4ГБ?

В Ubuntu самый удобный способ — использовать консольный архиватор **7z** (из пакета `p7zip-full`) с опцией `-v`, указав размер тома до 4 ГБ.

## Быстрый способ (7z)

1. Установите 7z, если ещё не установлен:
```bash
sudo apt update
sudo apt install p7zip-full
```

2. Создайте многотомный архив с томами ≤ 4 ГБ:
```bash
7z a -v3900m archive.7z /путь/к/файлу_или_папке
```

или, если хотите ровно 4 ГБ (но чуть меньше, чтобы гарантированно пройти FAT32):

```bash
7z a -v3999m archive.7z /путь/к/файлу_или_папке
```

или в гигабайтах:

```bash
7z a -v3.9g archive.7z /путь/к/файлу_или_папке
```

Параметры:

- `a` — добавить файлы в архив;
- `-v3900m` — разбить на тома по 3900 МБ (можно `m` — мегабайты, `g` — гигабайты);
- `archive.7z` — имя архива (будут созданы `archive.7z.001`, `archive.7z.002`, …).[^1_1][^1_2][^1_3]

3. Распаковка:
```bash
7z x archive.7z.001
```

7z сам найдёт все части и соберёт исходный файл.[^1_3]

## Альтернатива: tar + split

Если не хотите ставить 7z, можно сначала собрать tar-архив, потом разбить его:

```bash
tar -cvf backup.tar /путь/к/данным
split -b 3900M backup.tar backup.tar.part.
```

Получите файлы `backup.tar.part.aa`, `backup.tar.part.ab`, …

Сборка обратно:

```bash
cat backup.tar.part.* > backup.tar
tar -xvf backup.tar
```


## ZIP-вариант (если нужна максимальная совместимость)

```bash
zip -s 3900m -r archive.zip /путь/к/файлу_или_папке
```

Распаковка (на Linux):

```bash
zip -s 0 archive.zip -s 0 --out archive_full.zip
unzip archive_full.zip
```

Если скажете, для чего именно вам нужно разбиение (флешка FAT32, отправка по почте, загрузка в облако), могу подсказать оптимальный размер тома и формат.

# Как распаковать многотомный zip-архив на macos?

На macOS есть несколько способов распаковать многотомный ZIP-архив (файлы вида `archive.zip`, `archive.z01`, `archive.z02` или `archive.zip.001`, `archive.zip.002` и т.п.).[^2_1][^2_2][^2_3]

## 1. Самый простой способ — The Unarchiver

1. Установите **The Unarchiver** из Mac App Store (бесплатно).[^2_3][^2_4]
2. Положите все части архива в одну папку, не переименовывая их.[^2_1]
3. Откройте **первый файл** архива:
    - либо дважды кликните по нему в Finder,
    - либо правой кнопкой → **Open With** → **The Unarchiver**.[^2_3][^2_1]
4. The Unarchiver сам найдёт остальные части и извлечёт содержимое.[^2_4][^2_3]

## 2. Через Терминал (встроенный `unzip`)

Если части названы как `file.zip`, `file.z01`, `file.z02`…:

1. Откройте **Терминал** и перейдите в папку с файлами:

```bash
cd /путь/к/папке
```

2. Соберите части в один ZIP:

```bash
cat file.z01 file.z02 file.z03 file.zip > combined.zip
```

(порядок важен: сначала `.z01`, затем `.z02`, …, в конце `.zip`).[^2_2]
3. Распакуйте:

```bash
unzip combined.zip
```


Если части названы как `file.zip.001`, `file.zip.002`…:

```bash
cat file.zip.0* > combined.zip
unzip combined.zip
```


## 3. Встроенная «Архивная утилита» (Archive Utility)

Иногда достаточно:

- Положить все части в одну папку.
- Дважды кликнуть по **первому** файлу в Finder.

macOS может автоматически собрать и распаковать архив, но это работает не со всеми типами разбиения, поэтому для надёжности лучше использовать The Unarchiver или терминал.[^2_5][^2_4]

Если напишете, как именно называются ваши части (`.z01/.z02` или `.zip.001/.zip.002`), могу дать точную команду под ваш случай.

# Могу ли я вспользоваться способом 2, но не создавать явно `combined.zip`, т.е. выполнить склейку файлов "налету" и по "конвееру" передать в unzip?

Да, можно. В macOS (как и в Linux) `unzip` умеет читать архив из стандартного ввода, если указать `-` вместо имени файла.[^3_1]

## Вариант для `.z01`, `.z02`, …, `.zip`

```bash
cat file.z01 file.z02 file.z03 file.zip | unzip -
```


## Вариант для `.zip.001`, `.zip.002`, …

```bash
cat file.zip.001 file.zip.002 file.zip.003 | unzip -
```

Или, если частей много и они идут по порядку:

```bash
cat file.zip.* | unzip -
```

Важно:

- Порядок в `cat` должен быть правильным (по возрастанию номеров частей).
- Все части должны быть в одной папке и не переименованы.

Этот способ полностью эквивалентен созданию `combined.zip`, но без промежуточного файла на диске.[^3_2][^3_1]

# Для сжатия я использовал способ с утилитой `zip`, и параметром `-s`

На выходе получил два файла

- archive.zip
- archive.z01

Какой из этих файлов указывать первым при распаковке?

При распаковке **первым** нужно указывать файл с расширением **`.z01`**, а **последним** — **`.zip`**.[^4_1][^4_2]

В вашем случае:

```bash
cat archive.z01 archive.zip | unzip -
```

или, если хотите сначала собрать в файл:

```bash
cat archive.z01 archive.zip > combined.zip
unzip combined.zip
```

Логика такая: части нумеруются `.z01`, `.z02`, …, а финальный кусок всегда имеет расширение `.zip`. При склейке порядок должен быть строго по возрастанию номеров, заканчиваясь `.zip`.[^4_2][^4_1]
